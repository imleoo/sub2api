## 一、系统概述

TokenPanel 是一个**AI API 网关平台**，核心功能是将上游 AI 订阅账号（OpenAI、Antigravity、Gemini 等）的 API 凭证接入系统，通过 API Key 分发给用户使用。平台负责**认证计费、负载均衡、请求转发**，支持多租户、多账号池管理。

### 1.1 核心功能

| 功能模块 | 说明 |
|---------|------|
| **多账号管理** | 支持 OAuth/API Key/Cookie 等多种认证类型的上游账号 |
| **API Key 分发** | 为用户生成和管理 API Key，支持细粒度权限控制 |
| **智能调度** | 账号选择算法（优先级/负载/速率限制/粘性会话） |
| **精确计费** | Token 级用量追踪和成本计算 |
| **流量控制** | 用户/账号并发限制、请求频率限制 |
| **管理后台** | Web 界面用于监控和管理 |

## 三、后端架构详解

### 3.1 依赖注入（Wire DI）

项目使用 **Google Wire** 进行编译期依赖注入，所有 Provider 在 `wire.go` 文件中声明：

```
cmd/server/wire.go
├── config.ProviderSet           → 配置管理
├── repository.ProviderSet       → 数据访问层
├── service.ProviderSet          → 业务逻辑层（~60 个服务）
├── middleware.ProviderSet       → 中间件
├── handler.ProviderSet         → HTTP 处理器（85+ 个 handler 文件）
├── payment.ProviderSet         → 支付提供商
└── server.ProviderSet          → HTTP 服务器
```

**关键设计**：
- 所有后台服务（`TokenRefreshService`、`AccountExpiryService` 等）在 `wire.go` 的 `provideCleanup` 中注册优雅关闭逻辑
- 服务启动时调用 `Start()`，关闭时并行执行所有清理步骤，再顺序关闭基础设施（Redis → Ent）

### 3.4 Repository 层（数据访问）

```
repository/
├── account_repo.go     # Account 数据访问（Ent ORM）
├── user_repo.go        # User 数据访问
├── api_key_cache.go   # API Key 三级缓存（L1 内存 / L2 Redis / L3 DB）
├── gateway_cache.go   # 网关路由缓存（账号快照）
├── concurrency_cache.go # 并发槽位控制（Redis）
├── usage_log_repo.go  # 用量日志写入
├── dashboard_cache.go # 仪表盘数据缓存
├── billing_cache.go   # 计费结果缓存（Redis + singleflight）
├── gemini_token_cache.go # Token 缓存
└── ops_repo.go       # 运维数据存储
```

**缓存策略**：
- **API Key 认证缓存**：L1（Go 内存 map，TTL 10s）→ L2（Redis，TTL 60s）→ L3（PostgreSQL）
- **网关路由缓存**：定时快照（`SchedulerSnapshotService`）存储可调度账号列表，避免每次请求查 DB
- **计费缓存**：Redis + singleflight 防止缓存击穿

### 3.5 请求流转（Gateway Path）

```
Client Request (/v1/messages)
  │
  ├─ [Middleware Chain]
  │   ├─ bodyLimit         → 请求体大小限制
  │   ├─ clientRequestID   → 生成请求唯一 ID
  │   ├─ opsErrorLogger    → 捕获 handler 异常用于 OPS 日志
  │   ├─ endpointNorm      → 规范化请求端点
  │   ├─ apiKeyAuth       → API Key 鉴权 + 订阅验证
  │   └─ requireGroupAnthropic → 验证分组已分配
  │
  ├─ [Handler] h.Gateway.Messages
  │   ├─ 解析请求体，提取 model/user_id
  │   ├─ gatewayService.SelectAccount()    → 选择最优账号
  │   │   ├─ 从 SchedulerSnapshotCache 读取可用账号列表
  │   │   ├─ 按优先级/负载因子/速率限制过滤
  │   │   ├─ 粘性会话：同 session_id 路由到同一账号
  │   │   └─ 返回选中账号
  │   │
  │   ├─ gatewayService.ForwardRequest()  → 转发到上游
  │   │   ├─ Token 刷新（如需要）
  │   │   ├─ 构造上游请求（替换 base URL / header）
  │   │   ├─ HTTP/2 或 HTTP/1.1 上游调用
  │   │   └─ 流式响应透传 or 完整响应处理
  │   │
  │   ├─ billingService.Calculate()      → 计费
  │   │   ├─ 从 PricingService 获取模型定价
  │   │   └─ 计算 input_cost + output_cost
  │   │
  │   └─ usageRecordWorkerPool.Submit()  → 异步写用量日志
  │       └─ goroutine 批量写入 usage_logs 表
  │
  └─ [Response] 流式或完整响应返回客户端
```

### 3.6 中间件链

```
全局中间件（所有路由）：
  RequestLogger     → 结构化请求日志
  Logger           → Zap 日志
  CORS             → 跨域配置
  SecurityHeaders   → CSP / X-Frame-Options 等

API 网关中间件（/v1/*）：
  bodyLimit        → 请求体大小限制（默认 64MB）
  clientRequestID  → 请求 ID 生成
  opsErrorLogger   → OPS 异常捕获
  endpointNorm     → 端点规范化
  apiKeyAuth      → API Key 鉴权 + 计费执行
  requireGroup     → 分组验证（按平台返回对应错误格式）

Admin API 中间件（/api/v1/admin/*）：
  adminAuth        → JWT + Admin 角色验证

用户 API 中间件（/api/v1/keys/*）：
  jwtAuth          → JWT 验证
```

  created_at / user_agent / ip_address

### 4.2 关键设计决策

**软删除**：User/Account 等实体使用 `SoftDeleteMixin`，通过 `deleted_at IS NULL` 条件过滤已删除记录，避免数据丢失。

**JSONB 存储**：
- `Account.credentials`：认证凭证（API Key/OAuth Token/Session）
- `Account.extra`：平台特定扩展数据（如 CRS 同步的账户 ID）

**复合索引**：
```sql
CREATE INDEX usage_logs_user_id_created_at ON usage_logs (user_id, created_at);
CREATE INDEX usage_logs_api_key_id_created_at ON usage_logs (api_key_id, created_at);
CREATE INDEX accounts_platform_priority ON accounts (platform, priority) WHERE deleted_at IS NULL;
```

### 6.2 账号调度算法

```go
// GatewayService.SelectAccount() 简化逻辑
func (s *GatewayService) SelectAccount(ctx context.Context, groupID int64, model string) (*Account, error) {
    // 1. 从缓存读取可调度账号快照
    accounts := s.schedulerSnapshot.Get(groupID)

    // 2. 过滤条件
    candidates := accounts.Filter(func(a *Account) bool {
        if !a.IsSchedulable() { return false }        // 可调度
        if a.IsRateLimited() { return false }         // 非速率限制
        if a.IsOverloaded() { return false }           // 非过载
        if !a.SupportsModel(model) { return false }   // 支持模型
        return true
    })

    // 3. 粘性会话：优先选择上次使用的账号
    if lastAccount := s.stickySession.Get(sessionID); candidates.Contains(lastAccount) {
        return lastAccount, nil
    }

    // 4. 按优先级排序（priority 越小越优先）
    candidates.SortByPriority()

    // 5. 负载均衡：选择当前负载最低的账号
    return candidates.SelectByLoad(), nil
}
```

### 7.3 水平扩展

- **无状态设计**：Go 服务无内存状态（API Key 缓存/账号快照均存 Redis），可水平扩展
- **Redis 集群**：L2/L3 缓存层使用 Redis，支持多实例共享
- **PostgreSQL 主从**：读操作可路由到只读副本

---

## 八、关键设计模式

| 模式 | 应用场景 |
|------|---------|
| **三级缓存** | API Key 认证：L1 内存 → L2 Redis → L3 DB |
| **读写分离** | 计费：读缓存写 DB，用量日志异步批量写入 |
| **时间轮定时器** | 延迟任务（Token 刷新提醒、速率限制解除） |
| **幂等设计** | IdempotencyRecord 表防止重复扣费 |
| **错误透传** | ErrorPassthroughRule 配置决定哪些上游错误直接透传 |
| **Worker Pool** | 用量日志异步批量写入，避免阻塞响应 |
| **Singleflight** | 计费结果缓存防缓存击穿 |
| **Pub/Sub** | API Key 认证缓存 L1 失效通知（跨实例） |
