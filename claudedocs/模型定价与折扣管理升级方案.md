# 模型定价与折扣管理升级方案

> 版本：v1.0 | 日期：2026-05-18 | 状态：待审阅

## 一、背景与问题

当前模型定价存在以下结构性缺陷：

| 问题 | 现状 | 影响 |
|------|------|------|
| 定价数据无法在后台管理 | 只存在本地文件 + 内存，无 DB 记录 | 无法搜索、编辑单个模型定价 |
| 自定义模型维护困难 | 灵境/豆包等硬编码在 `injectCustomPricingModels()` | 上新模型必须改代码 |
| 模型白名单硬编码 | 前端 `useModelWhitelist.ts` 450+行静态列表 | 上新模型必须改代码 |
| 折扣系统粗粒度 | 只有全局 `map[string]float64`，无自定义定价 | 无法做精细化价格管理 |

---

## 二、确认的设计决策

| 决策点 | 结论 | 说明 |
|--------|------|------|
| 入库字段范围 | 仅计费字段（8个）+ display_name + description | 不入库 40+ 能力字段 |
| 白名单来源 | DB 全量搜索（不限平台） | 替换硬编码，支持账号添加时异步搜索 |
| 价格优先级 | `custom_cost ?? upstream_cost` 作为基准，再 × `discount_rate` | 自定义价格与折扣叠加 |
| 灵境模型处理 | 首次启动自动 seed 为 `is_custom=true` 的 DB 记录 | 迁移，不保留代码内置 |
| 旧折扣数据 | 从 `settings.model_discounts` 批量迁移到 `discount_rate` 字段 | 启动时一次性迁移 |

## 三、数据库新表：`model_pricings`

**文件**：`backend/ent/schema/model_pricing.go`（新建）

### 字段清单

| 字段 | 类型 | 说明 |
|------|------|------|
| `model_id` | string(200), unique | 模型标识符，如 `claude-opus-4-6` |
| `display_name` | string(200), nullable | 友好显示名称 |
| `description` | text, nullable | 模型介绍 |
| `provider` | string(100) | 提供商：`anthropic` / `openai` / `lingjing` 等 |
| `mode` | string(50) | `chat` / `image_generation` / `video_generation` |
| `input_cost_per_token` | decimal(30,10), nullable | 远端同步，USD/token |
| `output_cost_per_token` | decimal(30,10), nullable | 远端同步 |
| `cache_creation_input_token_cost` | decimal(30,10), nullable | 远端同步 |
| `cache_read_input_token_cost` | decimal(30,10), nullable | 远端同步 |
| `supports_prompt_caching` | bool, default false | 是否支持 prompt caching |
| `custom_input_cost` | decimal(30,10), nullable | 自定义覆盖输入价格 |
| `custom_output_cost` | decimal(30,10), nullable | 自定义覆盖输出价格 |
| `discount_rate` | decimal(10,4), nullable | 折扣率，null = 1.0（不打折） |
| `is_custom` | bool, default false | true=手动添加，false=远端同步 |
| `is_enabled` | bool, default true | 是否启用（影响用户侧可见性） |
| `last_synced_at` | timestamptz, nullable | 最后一次从远端同步的时间 |
| `created_at` | timestamptz | - |
| `updated_at` | timestamptz | - |

**索引**：`model_id`（唯一）、`provider`、`is_custom`、`is_enabled`

## 四、计费价格解析逻辑

**修改文件**：`backend/internal/service/billing_service.go`

```
// 原 applyDiscount() 升级为 resolveEffectivePrice()

base_input  = custom_input_cost  ?? input_cost_per_token   // 自定义优先
base_output = custom_output_cost ?? output_cost_per_token
rate        = discount_rate      ?? 1.0                    // 无折扣率时原价

final_input  = base_input  × rate                          // 叠加应用
final_output = base_output × rate
// cache cost 同理
```

**示例**：
- 模型上游输入价 `0.000003`，设了自定义价格 `0.000002`，折扣 `0.9`
- 实际计费 = `0.000002 × 0.9 = 0.0000018`

## 五、同步流程改造

**修改文件**：`backend/internal/service/pricing_service.go`

保留现有下载机制（URL + hash 校验 + 定时任务），下载完成后：

```
1. 解析 JSON，仅取 8 个计费字段
2. Upsert 到 model_pricings：
   - is_custom = false → 更新上游字段 + last_synced_at
   - is_custom = true  → 跳过，不覆盖
3. 从 DB 重建内存 map（不再从文件加载）
4. 本地文件保留作冷备份 / fallback
```

---

## 六、启动时一次性迁移

在 `PricingService.Initialize()` 中按序执行：

```
Step 1  远端同步 → upsert 到 DB（建立基础数据）
Step 2  Seed 灵境/豆包模型（来源：现 injectCustomPricingModels()）
        → INSERT IF NOT EXISTS，is_custom = true
Step 3  读取 settings.model_discounts（旧 map[string]float64）
        → 批量更新 model_pricings.discount_rate
        → 完成后可保留 settings key（兼容）或清除（清洁）
Step 4  从 DB 加载全部 is_enabled=true 的记录到内存 map
```

## 十二、风险点

| 风险 | 缓解措施 |
|------|---------|
| 旧折扣迁移后与新系统行为不一致 | 迁移前记录旧数据快照，迁移后对比计费结果 |
| 白名单选择器改为异步搜索，账号编辑体验变化 | 保持 loading/empty state，支持离线回显已选模型 |
| 灵境模型 seed 价格与代码内置价格不一致 | 迁移后删除 `injectCustomPricingModels()`，以 DB 为准 |
| 内存 map 从 DB 加载增加启动时间 | 批量查询（单次 `LoadAllEnabled`），影响可忽略 |
