# 代理商对账接口协议

## 1. 接口清单

| 接口 | 路径 | 用途 |
| --- | --- | --- |
| 用户余额查询 | `GET /api/v1/bill/balance` | 查询当前账号余额、当日/累计消耗，可附带指定 API Key 明细 |
| AI 调用日志查询 | `GET /api/v1/bill/logs` | 查询当前账号名下所有模型调用明细 |

使用前须知：

- 两条接口均使用 JWT 鉴权，详见 §2。
- 日志接口仅支持查询 T-1 及更早的已封闭历史区间，详见 §5.6。
- 所有响应均在顶层返回 `requestId`，用于异常排查时与服务端比对（见 §3）。

## 2. 鉴权

### 2.1 获取 JWT

代理商使用账号密码登录获取 `access_token`：

```bash
curl "https://{HOST}/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -X POST \
  -d '{"email": "agent@example.com", "password": "******"}'
```

响应（节选）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "..."
  }
}
```

后续请求统一使用 `data.access_token` 作为 Bearer Token。

### 2.2 请求头

| Header | 必填 | 说明 |
| --- | --- | --- |
| `Authorization` | 是 | `Bearer {access_token}` |
| `Accept` | 否 | `application/json` |
| `Accept-Language` | 否 | 错误消息本地化（如 `zh-CN`、`en-US`） |

> 服务端从 JWT 解析用户身份，**强制只返回当前账号自己的数据**，无法越权查询他人记录。

## 3. 通用响应契约

所有 `/api/v1/bill/*` 接口统一返回如下结构：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `requestId` | string | 是 | 本次调用的请求 ID（与服务端日志 trace_id 一致），用于排查问题 |
| `code` | int | 是 | 业务错误码，`0` 表示成功，非 `0` 表示失败 |
| `message` | string | 是 | 错误信息，成功时为 `success` |
| `data` | object \| null | 是 | 业务数据对象，错误时可能为 `null` |

`code` 与 HTTP 状态码相互独立，错误码见 §6。

## 4. 用户余额查询

### 4.1 接口信息

| 项目 | 值 |
| --- | --- |
| 接口路径 | `GET /api/v1/bill/balance` |
| 鉴权 | JWT（§2） |
| Content-Type | `application/json` |

### 4.2 查询参数 Query

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `api_keys` | string | 否 | 需要返回明细的 API Key 列表，每个元素为**完整 `sk-` 明文**，**逗号分隔**（如 `sk-aaa,sk-bbb`）；为空时返回当前账号全部 API Key 明细；最多 100 个。 |

> **传参约定**：
> - `api_keys` 必须使用 query string 的逗号分隔形式（如 `?api_keys=sk-aaa,sk-bbb`），不支持重复 key 形式（`?api_keys=sk-aaa&api_keys=sk-bbb`）。
> - 入参传明文是为了精确匹配；响应里 `api_keys_usage[].api_key` 始终返回脱敏形式，不会回显明文。

### 4.3 响应字段

#### 4.3.1 顶层字段

详见 §3 通用响应契约。

#### 4.3.2 `data` 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `data.balance` | number | 是 | 用户当前余额（单位：美元，精度同后台账户字段） |
| `data.today_actual_cost` | number | 是 | 当日累计实际消耗金额（美元） |
| `data.total_actual_cost` | number | 是 | 历史累计实际消耗金额（美元） |
| `data.api_keys_usage` | array&lt;object&gt; | 是 | API Key 使用明细列表；`api_keys` 入参为空时返回全部，否则返回指定列表 |
| `data.timestamp` | string (ISO 8601) | 是 | 查询时间，UTC 时间戳，格式 `YYYY-MM-DDTHH:mm:ssZ` |

所有金额字段均为**美元浮点数**。

#### 4.3.3 `data.api_keys_usage[]` 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `api_key` | string | 是 | API Key 的唯一标识（脱敏形式，如 `sk-xxx****yyyy`） |
| `today_actual_cost` | number | 是 | 当前 API Key 当日实际消耗金额（美元） |
| `total_actual_cost` | number | 是 | 当前 API Key 历史累计实际消耗金额（美元） |

### 4.4 成功响应示例

```json
{
  "requestId": "req_2026060611223344",
  "code": 0,
  "message": "success",
  "data": {
    "balance": 100.50,
    "today_actual_cost": 1.234567,
    "total_actual_cost": 88.901234,
    "api_keys_usage": [
      {
        "api_key": "sk-abc1****wxyz",
        "today_actual_cost": 0.00452025,
        "total_actual_cost": 0.27447609
      }
    ],
    "timestamp": "2026-06-06T10:01:02Z"
  }
}
```

### 4.5 示例 cURL

```bash
# 查询全部 API Key
curl "https://{HOST}/api/v1/bill/balance" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..." \
  -H "Accept: application/json"

# 仅查询指定 2 个 API Key（传完整 sk- 明文，响应里仍回脱敏字符串）
curl "https://{HOST}/api/v1/bill/balance?api_keys=sk-ant-api03-xxxxx,sk-ant-api03-yyyyy" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."
```

## 5. AI 调用日志查询

### 5.1 接口信息

| 项目 | 值 |
| --- | --- |
| 接口路径 | `GET /api/v1/bill/logs` |
| 鉴权 | JWT（§2） |
| Content-Type | `application/json` |

### 5.2 查询参数 Query

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `start_date` | string | 否 | 开始日期，格式 `YYYY-MM-DD`（按 `timezone` 解析） |
| `end_date` | string | 否 | 结束日期，格式 `YYYY-MM-DD`，**半开区间** `[start_date, end_date+1天)`；受 §5.6 T-1 约束 |
| `timezone` | string | 否 | 解析日期用的时区，如 `Asia/Shanghai`；缺省使用服务端默认时区 |
| `model` | string | 否 | 模型名称精确过滤 |
| `api_key` | string | 否 | 按指定 API Key 过滤，传**完整 `sk-` 明文**；不传则返回账号下所有 Key 的调用；非本人名下的 Key 返回 403 |
| `request_type` | string | 否 | 请求类型过滤 |
| `stream` | boolean | 否 | 是否流式（`true` / `false`） |
| `billing_type` | integer | 否 | 计费类型过滤 |
| `page` | integer | 否 | 页码，默认 `1` |
| `page_size` | integer | 否 | 每页条数，默认 `20`，最大 `1000`（兼容别名 `limit`） |
| `sort_by` | string | 否 | 排序字段，默认 `created_at`（亦支持 `model`、`id`） |
| `sort_order` | string | 否 | 排序方向，默认 `desc` |

### 5.3 响应字段

#### 5.3.1 顶层字段

详见 §3。

#### 5.3.2 `data` 字段（分页结构）

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 20,
  "pages": 1
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items` | array&lt;object&gt; | 当前页记录数组，元素字段见 §5.3.3 |
| `total` | int64 | 满足过滤条件的总记录数（受 §5.6 T-1 约束，区间固定后该值稳定） |
| `page` | int | 当前页码 |
| `page_size` | int | 当前页大小 |
| `pages` | int | 总页数 = `ceil(total / page_size)` |

#### 5.3.3 `items[]` 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `request_id` | string | 调用唯一请求 ID（与服务端日志 `trace_id` / `bill_request_id` 一致） |
| `created_at` | string (RFC3339) | 请求时间，如 `2026-04-28T10:00:00Z`（**非秒级时间戳**） |
| `model` | string | 实际调用的模型名称 |
| `input_tokens` | int | 输入 token 数 |
| `output_tokens` | int | 输出 token 数 |
| `cache_creation_tokens` | int | 缓存写入 token 数 |
| `cache_read_tokens` | int | 缓存读取 token 数 |
| `actual_cost` | number | 本次实际消耗费用（美元） |
| `api_key` | string | 脱敏后的 API Key 字符串（形式同 §4.3.3，如 `sk-abc1****wxyz`），与余额接口 `api_keys_usage[].api_key` 形态一致，可直接字符串相等比对 |
| 其它可用字段 | — | `total_cost`、`input_cost`、`output_cost`、`cache_*_cost`、`rate_multiplier`、`request_type`、`stream`、`duration_ms`、`group_id`、`subscription_id` 等 |

> 接口不返回完整 API Key 明文，也不返回服务端内部数字 ID。

### 5.4 成功响应示例

```json
{
  "requestId": "req_2026060611223345",
  "code": 0,
  "message": "success",
  "data": {
    "items": [
      {
        "request_id": "req_abc123",
        "created_at": "2026-06-05T10:00:00Z",
        "model": "claude-3-5-sonnet",
        "input_tokens": 1200,
        "output_tokens": 850,
        "cache_creation_tokens": 0,
        "cache_read_tokens": 0,
        "actual_cost": 0.012345,
        "api_key": "sk-abc1****wxyz"
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 20,
    "pages": 1
  }
}
```

### 5.5 示例 cURL

```bash
# 查询昨日（2026-06-05）claude 模型、第一页明细
curl "https://{HOST}/api/v1/bill/logs?start_date=2026-06-05&end_date=2026-06-05&model=claude-3-5-sonnet&page=1&page_size=100&timezone=Asia/Shanghai" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..." \
  -H "Accept: application/json"
```

### 5.6 T-1 对账窗口约束（**重要**）

**强制约束**：`end_date` 必须 ≤ "服务端按 `timezone` 解析后的昨日"，否则服务端直接返回 `400`（错误码 `INVALID_END_DATE`）。

**正反示例**（假设服务端日期为 `2026-06-06`，`timezone=Asia/Shanghai`）：

| `start_date` | `end_date` | 结果 |
| --- | --- | --- |
| `2026-06-05` | `2026-06-05` | ✅ 允许（昨日全天） |
| `2026-06-01` | `2026-06-05` | ✅ 允许（封闭历史区间） |
| `2026-06-05` | `2026-06-06` | ❌ 400（`end_date` 含当天） |
| `2026-06-06` | `2026-06-06` | ❌ 400（查询当天） |
| `2026-06-05` | `2026-06-07` | ❌ 400（`end_date` 指向未来） |

> **未传 `end_date` 时**：服务端默认填充为"按 `timezone` 解析后的昨日"，自动满足 T-1 约束；调用方可不传 `end_date` 简化逻辑。
>
> **未传 `start_date` 时**：服务端默认填充为 `end_date - 30 天`，避免一次性扫描超大区间。如需更大区间请显式传入。

### 5.7 推荐对账流程

代理商日常对账建议遵循以下 SOP：

1. **每日 T+1 凌晨**触发一次对账任务，固定 `start_date = end_date = T-1`。
2. 先调 `GET /api/v1/bill/balance`，记录当日账户余额与累计消耗作为对账锚点。
3. 再调 `GET /api/v1/bill/logs` 分页拉取 T-1 全天明细，循环至 `page > pages` 终止。
4. 本地按 `request_id` 做幂等去重作为防御性逻辑。
5. 若中途失败，断点续跑时**仅需重发未完成的 `page`**；同一 `page` 重复拉取结果一致。

## 6. 错误码

### 6.1 HTTP × 业务 code 对照

| HTTP | 业务 code | 含义 |
| --- | --- | --- |
| 200 | `0` | 成功 |
| 400 | 非 0 | 请求参数错误（含 T-1 校验失败、日期格式非法、`api_keys` 数量超限等） |
| 401 | 非 0 | 认证失败（JWT 缺失、过期或无效） |
| 403 | 非 0 | 越权（如查询的 `api_key` 不属于当前账号） |
| 429 | 非 0 | 触发限流，请退避后重试 |
| 500 | 非 0 | 服务器内部错误 |

### 6.2 业务错误码（`code` 字段）

> 具体错误码常量以服务端实现为准；以下为代理商需识别的常见错误：

| `code` 关键字 | 含义 | 建议处理 |
| --- | --- | --- |
| `INVALID_END_DATE` | `end_date` 违反 T-1 约束 | 将 `end_date` 改为 ≤ 昨日，重发请求 |
| `INVALID_DATE_FORMAT` | 日期格式非法 | 校正为 `YYYY-MM-DD` |
| `API_KEY_NOT_OWNED` | `api_key` / `api_keys` 不属于当前账号 | 移除越权 Key，重发请求 |
| `API_KEYS_TOO_MANY` | `api_keys` 数量超过上限（100） | 分批查询 |
| `TOKEN_EXPIRED` | JWT 过期 | 使用 `refresh_token` 续期或重新登录 |

## 7. 兼容承诺

- `/api/v1/bill/*` 路径**最少 6 个月**不做破坏性变更；如需破坏性变更，将以新版本路径并存方式提供过渡期。
- `data` 内字段允许**新增**，调用方需具备前向兼容能力；既有字段不会删除或重命名。
